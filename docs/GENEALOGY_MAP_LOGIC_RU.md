# Genealogy Map Logic — для генеалога

## 1. Цель модели
Модель должна сохранять:
- биографические сведения о персонах;
- типизированные родственные связи;
- степень достоверности фактов;
- конфликтующие версии данных через предложенные правки.

## 2. Основные сущности
- **Tree** — отдельное генеалогическое дерево.
- **Person** — персона.
- **Relationship** — связь между персонами (родитель, супруг).
- **Fact** — факт о персоне.
- **FactVersion** — история изменений факта.
- **ProposedChange** — предложенная правка.

## 3. Логика связей
- Parent-связь задаёт направление: `from_person -> to_person`.
- Self-relationship запрещён.
- Связи ограничены рамками одного дерева.

## 4. Достоверность данных
Рекомендуемая интерпретация уровня `confidence`:
- A — подтверждено документом.
- B — подтверждено косвенно/свидетельствами.
- C — семейное предание.

## 5. Конфликты данных
Когда родственники дают разные данные:
1. Создаётся `ProposedChange`.
2. Владелец дерева проверяет аргументы и источники.
3. Правка одобряется или отклоняется.
4. Решение фиксируется в статусе и аудите.

## 6. GEDCOM и межсистемный обмен
- Экспорт сохраняет персон и базовые parent-связи.
- Импорт читает `INDI/NAME/BIRT/DEAT/FAM/HUSB/CHIL`.
- Для научной генеалогии рекомендуется ручная верификация после импорта.

## 7. Методологические рекомендации
- Указывать источники каждого значимого факта.
- Отмечать сомнительные данные как гипотезы.
- Не удалять противоречия без протокола решения.
- Поддерживать хронологию миграций семьи в биографиях.
